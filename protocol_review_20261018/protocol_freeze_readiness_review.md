## 1. Executive Summary & Readiness Verdict

We conducted a comprehensive, read-only reproducibility and methodology review to determine whether the proposed benchmark protocol (`Protocol v3`) is ready to be frozen for execution.

### Protocol Readiness Verdict: **CONDITIONAL APPROVAL (3 CRITICAL BLOCKS TO RESOLVE)**
While Protocol v3 resolves the catastrophic failure modes of the legacy experiment (eliminating 0%-exposure channels, fixing run-count arithmetic, and adopting a randomized complete block design), **the protocol cannot be frozen in its current draft state** until three methodological and technical ambiguities are resolved:
1. **Multimodal Vision Confound:** Protocol v3 enables vision (`use_vision=True`). In the `VIS` arm, the target fact is rendered visually on screen, providing multimodal dual-channel reinforcement (Text + Image). In `ARIA` and `DATA-CFG`, the fact exists only in DOM attributes and is completely absent from visual screenshots. This confounds channel delivery with text vs vision processing.
2. **Verifier Substring False-Positive Vulnerability:** For retrieval tasks (T1–T5), using naive substring matching on discrete numbers (e.g. checking for `"36"` or `"43"`) triggers false positives when an agent outputs a refusal or negative assertion (e.g. *"I searched the page and found no warranty of 36 months"*).
3. **Negative Control (`ABS`) Scoring Objective:** Protocol v3 omits whether `ABS` is evaluated as a **Hallucination Test** (where outputting the absent fact scores `0`, expected accuracy $\approx 0\%$) or a **Refusal Accuracy Test** (where outputting *"information unavailable"* scores `1`).

### 2. Confirmed Modality Confound (`use_vision=True`)
- **Confirmed Fact:** Under `browser-use 0.13.10`, calling `Agent(..., use_vision=True)` sends both a serialized text DOM and a high-resolution screenshot to multimodal LLMs (e.g. Gemini 2.5 Flash Lite).
- **The Confound:** 
  - In `VIS`, the LLM receives the fact in **both** the text prompt and the image prompt.
  - In `ARIA` and `DATA-CFG`, the fact exists **only** in the text DOM; the image prompt shows only standard button text without the attribute.
  - If `VIS` outperforms `ARIA` or `DATA-CFG`, the researcher cannot determine whether the advantage stems from DOM markup semantics vs multimodal visual reinforcement.
- **Proposed Design Decision:**
  - *Option A (Pure Text Benchmark - Recommended):* Set `use_vision=False`. This isolates DOM token processing and eliminates visual leakage.
  - *Option B (Factorial 2x4 Design):* Evaluate `Vision (True/False) × Channel (ABS/VIS/ARIA/DATA-CFG)`.

## 4. Review Area 3: Initial-State & Action-Evidence Requirements

### 1. Browser State Isolation & Cache Vulnerability
- **Confirmed Fact:** Under `browser-use 0.13.10`, `BrowserSession(keep_alive=True)` does not clear HTTP memory/disk caches across sequential navigation steps by default.
- **Risk:** If an agent visits variant `v0-baseline` on `http://localhost:8080` and then subsequently navigates to `v1-jsonld`, cached responses of `products.js` or HTML fragments may be served.
- **Protocol Requirement:** The runner must explicitly issue CDP commands at the start of every trial:
  ```python
  await cdp_session.send("Network.setCacheDisabled", {"cacheDisabled": True})
  await browser_context.clear_cookies()
  await setup_page.evaluate("() => { localStorage.clear(); sessionStorage.clear(); }")
  ```

### 2. Action Evidence for Retrieval Tasks (T1–T5)
- **Pre-Condition:** Agent begins at a neutral home page (`http://localhost:8080/#home`).
- **Causal Evidence:** 
  1. CDP navigation history must prove the agent navigated to the specific product details page.
  2. If the agent outputs the correct lot code without navigating to the page, the trial is flagged as a contamination/leakage failure.

### 2. Randomization Scheme (Randomized Complete Block Design - RCBD)
- **Implementation:** Within each block of 24 runs, the trial order is pseudo-randomly permuted using a fixed reproducible seed:
  ```python
  import random
  def generate_trial_schedule(seed=20261020, blocks=4):
      random.seed(seed)
      schedule = []
      cells = [(arm, task) for arm in ["ABS", "VIS", "ARIA", "DATA-CFG"] for task in ["T1", "T2", "T3", "T4", "T5", "T6"]]
      for b in range(1, blocks + 1):
          block_trials = list(cells)
          random.shuffle(block_trials)
          for arm, task in block_trials:
              schedule.append({"block": b, "arm": arm, "task": task})
      return schedule
  ```
- **Robustness Against Truncation:** If execution stops unexpectedly at run #55, complete blocks 1 and 2 (runs 1–48) are **100% balanced across all 24 cells**, completely eliminating the sequential block confounding of the legacy experiment.

### 3. Quota Constraints & Circuit Breaker
- **Empirical Request Rate:** In the legacy experiment, runs averaged ~4.7 steps (range 1–15).
  - For $N = 96$ runs: $96 \times 6\text{ steps} \approx \mathbf{576\text{ API requests}}$.
  - For $N = 120$ runs: $120 \times 6\text{ steps} \approx \mathbf{720\text{ API requests}}$.
- **Free Tier Constraint:** Google Gemini free-tier quota is hard-capped at **500 requests per day**.
  - **Confirmed Fact:** Attempting to execute 96 runs in a single 24-hour window using a free-tier API key will trigger HTTP 429 quota exhaustion at approximately run #80–85.
  - **Required Protocol Solution:**
    - *Option A:* Use a Gemini API key with billing enabled (Pay-As-You-Go tier). Quota is 1,000–4,000 RPM with no daily 500 request wall. Total cost for 96 runs is estimated at $< \$0.50$.
    - *Option B:* Split execution across 2 scheduled days (Block 1 & 2 on Day 1; Block 3 & 4 on Day 2).
- **Circuit Breaker:** If two consecutive runs encounter HTTP 429, the runner terminates execution immediately. Selective reruns are strictly prohibited.

## 6. Review Area 5: Statistical Power Assumptions & Primary Outcome

### 1. Primary Statistical Outcome
- **Metric:** Binary Retrieval Correctness ($Y_{ijk} \in \{0, 1\}$).
- **Statistical Model:** Generalized Linear Mixed Model (GLMM) with a logit link function:
  $$\text{logit}(P(Y_{ijb} = 1)) = \beta_0 + \beta_{ARIA} X_{ARIA} + \beta_{DATA} X_{DATA} + \beta_{ABS} X_{ABS} + u_j + v_b$$
  where $u_j \sim \mathcal{N}(0, \sigma_u^2)$ accounts for task clustering, and $v_b \sim \mathcal{N}(0, \sigma_v^2)$ accounts for block clustering.

### 3. Claim Validity Constraints
- **Unverified & Prohibited Claim:** If $p > 0.05$ between `ARIA` and `VIS`, the paper **cannot** claim that *"ARIA is as effective as visible text"*. With $N = 24$ per arm, the test has a 76.7% probability of missing a 15-percentage-point difference.
- **Verified & Permissible Claim:** Protocol v3 is calibrated to detect **large channel degradation ($\Delta \ge 0.40$)** or validate presence vs absence ($\Delta \ge 0.70$). Negative findings must be reported with 95% confidence intervals setting an upper bound on effect sizes.

## 8. Specific Modifications Required Prior to Protocol Freeze

Before taking the final step to freeze the protocol and author implementation files, the following 3 adjustments must be formally incorporated:

1. **Resolve Vision Modality:** Explicitly declare whether the benchmark is:
   - **Text-Only DOM Benchmark (Recommended):** Set `use_vision=False`. Guarantees identical token modalities across all arms.
   - **Multimodal Visual Benchmark:** Retain `use_vision=True`, but document in the paper that `VIS` has a visual reinforcement channel not available to DOM attribute channels.
2. **Harden Verifier Logic Against False Positives:**
   - Replace discrete integer targets in T1, T3, T4 with synthetic alphanumeric tokens (e.g., `WAR-38M`, `BIN-43X`, `RET-49D`).
   - Implement regex-anchored extraction rather than substring inclusion to reject agent refusal sentences.
   - Explicitly specify that `ABS` trials evaluate hallucination rate (scoring `0` if token is output; `1` if correctly rejected).
3. **Formalize API Quota Strategy:**
   - Formally specify whether execution will use a billing-enabled API key (Pay-As-You-Go, $<\$0.50$ cost) or a 2-day split schedule to stay within the 500 requests/day free tier.
