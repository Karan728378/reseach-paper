def sanitize_secret_leakage(text: str) -> str:
    if not isinstance(text, str):
        return text
    api_key = os.environ.get("GOOGLE_API_KEY")
    if api_key and len(api_key) > 5:
        text = text.replace(api_key, "[REDACTED_API_KEY]")
    text = re.sub(r'AIza[0-9A-Za-z\-_]{35}', '[REDACTED_API_KEY]', text)
    text = re.sub(r'(?i)bearer\s+[a-zA-Z0-9_\-\.]{20,}', 'Bearer [REDACTED_TOKEN]', text)
    return text

    """

    Only runs with fatal infrastructure aborts (e.g. status='quota_aborted')

    if not summary_csv.exists():

    with summary_csv.open("r", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        for row in reader:
            idx = row.get("run_index") or row.get("scheduled_run_index")
            status = row.get("status", "completed")
            if idx and str(idx).isdigit() and status == "completed":
                completed.add(int(idx))
    return completed

## 1. Research Question and Empirical Framing

### 1.1 Research Question
> **Does augmenting a website that already displays factual information in visible text with structured semantic markup (WAI-ARIA accessibility attributes or configured custom `data-*` attributes) improve an autonomous text-based browser agent's task accuracy, execution efficiency (step count), and latency compared to unaugmented visible HTML?**

### 1.2 Scientific Framing: Option A (Additive Semantic Markup Evaluation)
In modern web development, websites display product names, prices, ratings, and stock status directly in human-visible typography (`<span>$49.99</span>`). In addition, developers frequently layer machine-readable metadata on top of visible elements:
1. **WAI-ARIA semantics:** Roles and accessible labels (`aria-label="Price: $49.99"`, `role="img" aria-label="Rating: 4.5 out of 5 stars"`) designed for assistive technologies.
2. **Custom `data-*` attributes:** Machine-readable hooks (`data-amount="49.99"`, `data-product-id="wh-001"`, `data-action="add-to-cart"`) designed for client-side scripts, telemetry, and automated testing.

Prior literature has assumed that browser agents either require visual perception or process raw HTML indiscriminately. This experiment measures whether adding structured semantic markup provides measurable advantages to an LLM agent operating in text-only DOM mode (`use_vision=False`).

## 5. Experimental Design, Randomization, and Execution Engine

### 5.1 Design Structure
- **Design:** Randomized Complete Block Design (RCBD).
- **Total Sample Size:** $N = 96$ runs ($K=4$ schedule arms $\times$ $J=6$ tasks $\times$ $R=4$ blocks).
- **Primary Analysis Sample Size:** $N_{\text{primary}} = 80$ runs (Tasks T1â€“T5 across 4 blocks).
  - Pooled Baseline: $n = 40$ runs ($8$ per task).
  - ARIA: $n = 20$ runs ($4$ per task).
  - DATA-CFG: $n = 20$ runs ($4$ per task).
- **Secondary Probe Sample Size:** $N_{\text{probe}} = 16$ runs (Task T6 across 4 blocks).

### 5.2 Deterministic Schedule Consumption
- The execution engine (`protocol_v3_runner.py`) consumes `proposed_randomized_schedule.csv` sequentially.
- Within-block order is randomized and fixed in advance to guarantee exact reproducibility.

### 5.3 Survivorship Bias Correction
- In historical runners, `get_completed_run_indices` filtered on `success==True`, causing failed runs to be retried on restart.
- In `protocol_v3_runner.py`, both `success=True` and `success=False` are marked as **COMPLETED**.
- Completed failed runs are **never retried**. Only fatal infrastructure crashes (e.g. HTTP 429 quota exhaustion) are eligible for resumption.

### 5.4 Post-Experiment Analysis Pipeline (`analyze_v3_results.py`)
- Automated analysis is executed via `analyze_v3_results.py`.
- **Primary Model:** Task-Stratified Cochran-Mantel-Haenszel (CMH) test across T1â€“T5 ($N=80$) with Bonferroni correction ($\alpha_{\text{adj}} = 0.05 / 3 = 0.0167$).
- **Effect Sizes:** Risk Differences reported with Newcombe Hybrid Score CIs and Agresti-Caffo Adjusted Wald CIs.
- **Mandatory Non-Equivalence Rule:** Because power for small effects ($\Delta \le 0.20$) is $< 20\%$ (and $< 11\%$ under task clustering), non-significant tests ($p \ge \alpha_{\text{adj}}$) cannot be claimed as channel equivalence.

## 3. Statistical Testing Framework

### 3.1 Primary Inferential Model: Cochran-Mantel-Haenszel (CMH) Test
- **Specification:** Stratified across the 5 primary benchmark tasks ($J=5$) to control for task-difficulty clustering.
- **Hypothesis:** Tests the conditional independence of treatment arm and task success given task stratum:
  $$\chi_{\text{CMH}}^2 = \frac{\left(\sum_{j=1}^5 (O_j - E_j)\right)^2}{\sum_{j=1}^5 \operatorname{Var}(O_j)}$$
- **Multiple Comparisons:** Bonferroni adjustment for the 3 primary contrasts: $\alpha_{\text{adj}} = 0.05 / 3 \approx 0.0167$.

### 3.2 Generalized Linear Mixed Model (GLMM) Status
- **Planned Model Specification:**
  $$\operatorname{logit}\left(P(Y_{ijk} = 1)\right) = \beta_0 + \sum_{m=1}^{2} \beta_m \cdot \operatorname{Arm}_{m, i} + \sum_{l=1}^{4} \gamma_l \cdot \operatorname{Task}_{l, j} + u_k$$
  where $u_k \sim \mathcal{N}(0, \sigma_b^2)$ represents the random intercept for execution block $k \in \{1, 2, 3, 4\}$.
- **Audit & Implementation Status:** Marked as `OFFLINE_DEPENDENCY_ABSENT`. In accordance with methodological standards, ordinary logistic regression is NOT substituted because treating clustered block measures as independent would deflate standard errors. The task-stratified CMH test serves as the primary verified inferential model.
- **Pipeline Implementation:** Fully implemented and validated in [`analyze_v3_results.py`](file:///C:/testing/research_execution_20261018/analyze_v3_results.py).

### 3.3 Marginal Descriptive Tests & Risk Difference Confidence Intervals
- Evaluated on pooled $2 \times 2$ contingency tables as an unadjusted marginal summary.
- Effect size reported as Risk Difference ($\widehat{RD} = p_{\text{treat}} - p_{\text{base}}$).
- **Confidence Intervals:** Evaluated using:
  1. **Newcombe Hybrid Score Interval (Newcombe 1998, Method 10):** Combines individual Wilson score limits; strictly bounded in $[-1, +1]$; handles zero cells robustly.
  2. **Agresti-Caffo Adjusted Wald Interval (Agresti & Caffo, 2000):** Adjusted Wald interval with +4 pseudo-observations.

## 4. Power Calculations & Dependence Assumptions

### 4.1 Reconciled Statistical Power Estimates
As established in [`POWER_RECONCILIATION.md`](file:///C:/testing/research_execution_20261018/final_review/POWER_RECONCILIATION.md), two distinct calculations exist in the repository, representing complementary modeling assumptions:
1. **Model 1: Idealized Homogeneous Binomial Benchmark:** Assumes independent binomial trials ($\rho = 0$) from a single homogeneous pool with uniform baseline $P=0.50$.
2. **Model 2: Realistic Task-Heterogeneous RCBD Simulation (`recompute_power_rcbd.py`):** Models the actual 5-task RCBD structure with heterogeneous task baselines $[0.70, 0.85, 0.50, 0.30, 0.80]$, cell sizes $n=4$/task, and probability boundaries $[0.05, 0.95]$.

| Contrast Scenario | Assumed Shift ($\Delta$) | Model 1: Idealized Homogeneous Binomial ($N=40$ vs $20$, $\alpha=0.0167$) | Model 2: Task-Heterogeneous RCBD Simulation ($B=2000$, $\alpha=0.0167$) | Methodological Implication |
|---|---|---|---|---|
| **Large Disparity**   | $\Delta = 0.70$ ($0.10 \to 0.80$) | **99.9%** (Analytic) | **98.8% $\pm 0.2\%$** (RCBD) | Adequately powered under both models |
| **Moderate Effect**   | $\Delta = 0.35$ ($0.50 \to 0.85$) | **65.1%** (Analytic) | **49.7% $\pm 1.1\%$** (RCBD) | Moderately/marginally powered; ~50% risk of Type II error |
| **Small Effect**      | $\Delta = 0.20$ ($0.65 \to 0.85$) | **19.8%** (Analytic) | **10.8% $\pm 0.7\%$** (RCBD) | **Severely underpowered** |
| **Subtle Difference** | $\Delta = 0.15$ ($0.70 \to 0.85$) | **9.9%**  (Analytic) | **5.7% $\pm 0.5\%$**  (RCBD) | Inconclusive (near nominal alpha) |

### 4.2 Explicit Caveat: Intra-Cluster Correlation and Effective Sample Size
- Trials within the same task share task difficulty (intra-task correlation $\rho_{\text{task}} > 0$).
- When $\rho > 0$, effective sample size is reduced ($N_{\text{eff}} < N$), explaining why the realistic RCBD simulation yields lower power (49.7%) than the unstratified homogeneous binomial model (65.1%).
- This reinforces why the **Task-Stratified CMH Test** is designated as the primary inferential model.

### 4.3 MANDATORY NON-EQUIVALENCE RULE
> **Strict Methodological Prohibition:**  
> Because statistical power is under 20% for small-to-moderate effects ($\Delta \le 0.20$) across both models, **a failure to reject the null hypothesis ($p \ge \alpha$) CANNOT and MUST NOT be claimed as evidence of "channel equivalence" or proof that semantic markup provides no benefit.** Any non-significant contrast must be reported strictly as **statistically inconclusive due to sample size constraints**.

## 2. Treatment Construction & Confounding Analysis

### 2.1 The Target-Text Co-Location Confound in `v2-aria`
In [`shared/app-core.js:Line 243`](file:///C:/testing/shared/app-core.js#L243):
```javascript
if (F.aria) addBtn.setAttribute('aria-label', 'Add ' + product.name + ' to cart');
```
- In `v0-baseline` (ABS and VIS), all product buttons render as: `[12] <button>Add to Cart</button>`. To select the correct button, the agent must perform **hierarchical reference resolution**: read the card's heading (`<h3>SoundFlow Air 3</h3>`), inspect the price (`$49.99`), find the card boundary, and identify the specific button index corresponding to that card.
- In `v2-aria`, the button renders as: `[12] <button aria-label="Add SoundFlow Air 3 to cart">Add to Cart</button>`.
- **The Confound:** The agent no longer needs to perform hierarchical reference resolution. It simply searches the serialized prompt for the string `"SoundFlow Air 3"` and clicks the button containing that exact label. Any observed improvement in agent accuracy reflects **element-label disambiguation**, not semantic markup comprehension.

### 2.2 Developer Attribute Injection in `v3-data-attrs`
In [`shared/app-core.js:Lines 245â€“247`](file:///C:/testing/shared/app-core.js#L245-L247):
```javascript

  addBtn.setAttribute('data-action', 'add-to-cart');
```

- Custom developer attributes (`data-action`, `data-product-id`) are retained on `<button>` elements only because [`protocol_v3_runner.py:L32`](file:///C:/testing/research_execution_20261018/protocol_v3_runner.py#L32) supplies `EXTENDED_ATTRIBUTES`.

### 4.3 The Equivalence Fallacy Warning
> [!WARNING]
> **STRICT BAN ON EQUIVALENCE CLAIMS:**  
> Because the statistical power to detect a realistic 15â€“20% performance improvement is under $11\%$, obtaining a non-significant result ($p > 0.05$) **cannot be claimed as evidence that plain HTML and semantic markup perform equivalently**.  
> Proving equivalence requires a Two One-Sided Tests (TOST) equivalence testing framework with an a priori equivalence margin (e.g., $\delta = \pm 0.10$). At $\delta = 0.10$, establishing equivalence with $80\%$ power requires $N \ge 340$ trials per arm ($N \ge 1,360$ total trials). Claiming equivalence at $n=20$ is mathematically invalid.

## 5. Multiple Testing & Baseline Stability Control

### 5.1 Multiplicity Adjustment
To control Family-Wise Error Rate (FWER) across the family of 3 primary orthogonal contrasts ($C_1$: ARIA vs BASELINE, $C_2$: DATA-CFG vs BASELINE, $C_3$: ARIA vs DATA-CFG), [`analyze_v3_results.py`](file:///C:/testing/research_execution_20261018/analyze_v3_results.py) applies a strict Bonferroni correction:
$$\alpha_{\text{adjusted}} = \frac{0.05}{3} \approx 0.0167$$

### 5.2 Baseline Stability Quality Control
Protocol v3 includes two identical baseline arms (`BASELINE` and `BASELINE_REP`), both pointing to `v0-baseline`.
- **Quality Control Rule:** A two-sided Fisher's exact test is conducted comparing `BASELINE` ($n=20$) vs `BASELINE_REP` ($n=20$).
- **Decision Rule:**
  - If $p \ge 0.10$, stability is affirmed, and baselines may be pooled into an $N=40$ reference baseline.
  - If $p < 0.10$, baseline drift is declared; pooling is suspended, and separate unpooled contrasts are reported.
- **Audit Limitation:** With $n=20$ per arm, Fisher's exact test has low power to detect baseline divergence. Even if success rates drift by 15% (e.g., 60% vs 75%), Fisher's test yields $p \approx 0.50$. Consequently, the pipeline always exports unpooled sensitivity contrasts regardless of the stability test outcome.

## 3. Why Historical Data Cannot Be Pooled with Protocol v3

Attempting to combine or pool data from Experiment 1 or 1b into Protocol v3 would violate fundamental principles of scientific experimental design:

1. **Modality Incompatibility (`use_vision=True` vs `use_vision=False`):**  
   In Experiments 1 and 1b, the model received full rendered screenshots of the webpage. The agent was able to navigate using visual layout, button colors, and rendered typography, rendering DOM text markup differences largely irrelevant. 2. **Treatment Delivery Divergence:**  
   In Experiment 1, custom `data-*` attributes and JSON-LD never entered the LLM prompt. In Protocol v3, `data-*` attributes are verified to reach the prompt via the extended whitelist patch. Pooling them would combine "untreated" trials with "treated" trials under the same label.
3. **Verifier Construct Shift:**  
   In Experiment 1, a run on T3 was scored as a success if the agent added *any* headphone or earbud to the cart (100% artificial ceiling). In Protocol v3, T3 strictly evaluates whether the agent identified the second-highest rated item (`wh-002`). Combining these would contaminate the outcome variable $Y_{ijk}$.
4. **Survivorship Bias Contamination:**  
   Experiment 1's cleaned summary excluded domain failures and retried until success. Protocol v3 logs failures permanently, guaranteeing unbiased effect estimation.

## 2. Treatment Delivery Audit & Empirical Evidence

### 2.1 The DOM Serializer Bottleneck in `browser-use 0.13.10`
In standard web development, developers assume that any HTML attribute or `<script>` tag added to the DOM is visible to software interacting with the page. However, browser automation frameworks serialize the DOM into a token-limited text representation before passing it to the LLM.

Audit of [`browser-use 0.13.10`](file:///C:/testing/.venv/Lib/site-packages/browser_use/) revealed two critical architectural constraints:

1. **Element Pruning (`DISABLED_ELEMENTS`):**  
   In `browser_use/dom/serializer/serializer.py` (line 18):
   ```python
   DISABLED_ELEMENTS = {'style', 'script', 'head', 'meta', 'link', 'title'}
   ```
   Any element matching this set is stripped immediately.
   - **Empirical Finding:** `<script type="application/ld+json">` elements are unconditionally pruned. **JSON-LD NEVER reaches the LLM observation buffer.**
   - **Methodological Rule:** JSON-LD cannot be evaluated as an active agent delivery channel under standard `browser-use 0.13.10`. It is excluded from the primary experimental arms of Protocol v3.
2. **Attribute Filtering (`DEFAULT_INCLUDE_ATTRIBUTES`):**  
   In `browser_use/dom/views.py` (line 18), attributes are filtered against a hardcoded whitelist.
   - Standard `aria-label` on `<button>` elements is included by default.
   - Standard `aria-label` on non-interactive `<span>` elements is omitted.
   - Custom attributes (`data-action`, `data-product-id`, `data-category-slug`) are stripped by default.
   - **Harness Resolution:** [`protocol_v3_runner.py`](file:///C:/testing/research_execution_20261018/protocol_v3_runner.py) supplies `EXTENDED_ATTRIBUTES` to the `Agent` constructor, successfully exposing configured `data-*` attributes.

## 3. Two-Tier Task Architecture & Verifier Hardening

Historical pilot experiments suffered from construct contamination because retrieval tasks, cart mutation tasks, and absent-fact probes were scored under inconsistent, loose verifiers. Protocol v3 establishes a strict two-tier architecture:

### 3.1 Primary Grounded Benchmark (Tasks T1â€“T5, $N=80$)
These tasks are grounded in visible page facts and application state:
- **Task T1 (Cheapest Wireless Headphone):** Target `wh-001` ($49.99). Verifier checks exact SKU in cart.
- **Task T2 (Mechanical Keyboard Pro):** Target `mkp-001` ($149.99). Verifier checks exact SKU in cart.
- **Task T3 (Second-Highest Rated Audio Product):** Target `wh-002` (BudPro Wireless X, rating 4.5; highest is `wh-003` at 4.8). Verifier strictly enforces `len(cart) == 1` and `cart[0] == "wh-002"`. Rejects multi-item carts or wrong SKUs (resolving historical flaw where 6 SKUs passed).
- **Task T4 (Mouse Checkout):** Target `mse-001` ($29.99). Verifier strictly checks `order_confirmed == True` and order items containing `mse-001` (resolving historical flaw awarding 0.25 on incomplete checkouts).
- **Task T5 (Cart Mutation):** Remove item from cart. Verifier asserts initial pre-state (`pre_cart_count == 1`) before checking empty final cart (`len(cart) == 0`). Aborts on setup failure, eliminating vacuous passes.

### 3.2 Exploratory Negative Probe (Task T6, $N=16$)
- **Context:** Manufacturer warranty duration is completely absent from all site variants and catalogs.
- **Construct Measured:** Hallucination resistance vs grounded refusal under prompt pressure.
- **Scoring Isolation:** Evaluated separately via refusal regex (`refusal_detected`). Prohibited from pooling into primary task completion accuracy.

## 4. Statistical Power & Strict Ban on Equivalence Claims

In [`POWER_RECONCILIATION.md`](file:///C:/testing/research_execution_20261018/final_review/POWER_RECONCILIATION.md), power calculations across 10,000 Monte Carlo trials in `recompute_power_rcbd.py` established:

- **Large Disparity ($\Delta = 0.70$):** $98.6\%$ power (robustly detectable).
- **Moderate Effect ($\Delta = 0.35$):** $49.7\%$ power (moderate detection sensitivity).
- **Small Effect ($\Delta = 0.20$):** $10.8\%$ power (**severely underpowered**).
- **Subtle Effect ($\Delta = 0.15$):** $5.8\%$ power (indistinguishable from nominal $\alpha$).

> [!WARNING]
> **METHODOLOGICAL RULE â€” STRICT BAN ON EQUIVALENCE CLAIMS:**  
> Because the experiment has $<11\%$ power to detect small differences ($\Delta \le 0.20$), a non-significant result ($p > 0.05$) CANNOT be claimed as evidence of "channel equivalence" or that semantic markup "does not matter." It proves only that the sample size ($N=20$/arm) was insufficient to detect subtle effects.

### Mechanism 1: Tag-Level Pruning (`DISABLED_ELEMENTS`)
In [`serializer.py:Line 18`](file:///C:/testing/.venv311/Lib/site-packages/browser_use/dom/serializer/serializer.py#L18):
```python
DISABLED_ELEMENTS = {'style', 'script', 'head', 'meta', 'link', 'title'}
```
During tree traversal in `_create_simplified_tree` ([`serializer.py:L480-L482`](file:///C:/testing/.venv311/Lib/site-packages/browser_use/dom/serializer/serializer.py#L480-L482)):
```python
elif node.node_type == NodeType.ELEMENT_NODE:
    if node.node_name.lower() in DISABLED_ELEMENTS:
        return None
```
When `return None` executes, traversal terminates for that entire branch. Neither the node nor any child nodes are processed. Consequently, structured search indexing formats (`<script type="application/ld+json">`) and verification timestamps (`<meta name="evidence-date">`) are destroyed before the agent ever observes the page.

### Mechanism 2: Non-Interactive Element Attribute Stripping
In [`serializer.py:Lines 1046â€“1058`](file:///C:/testing/.venv311/Lib/site-packages/browser_use/dom/serializer/serializer.py#L1046-L1058):
```python

    node.is_interactive

    ...
    attributes_html_str = DOMTreeSerializer._build_attributes_string(
        node.original_node, include_attributes, text_content

```
If an element is **not interactive** (not clickable, not scrollable, and not a frame):
- `_build_attributes_string` is **never called**.
- No tag line `<span ...>` or `<div ...>` is emitted in the serialized observation.
- The serializer recursively processes child text nodes, emitting pure textual strings (e.g. `$49.99` or `4.5`), but all parent attributes (`aria-label`, `data-amount`, `data-rating`, `role="img"`) are discarded.

### Mechanism 3: Whitelist Filtering & Empty Attribute Pruning
In [`serializer.py:Lines 1211â€“1215`](file:///C:/testing/.venv311/Lib/site-packages/browser_use/dom/serializer/serializer.py#L1211-L1215):
```python
attributes_to_include.update(
    {
        key: str(value).strip()
        for key, value in node.attributes.items()
        if key in include_attributes and str(value).strip() != ''
    }

```
1. **Whitelist Exclusion:** If `key not in include_attributes`, the attribute is dropped. Because `DEFAULT_INCLUDE_ATTRIBUTES` in `views.py:L18` contains `aria-label` but omits `data-action` or `data-product-id`, developer custom attributes are stripped by default.
2. **Empty Attribute Stripping:** Attributes where `str(value).strip() == ''` (such as placeholder attributes `aria-label=""` or `data-action=""`) are pruned.

Using our reproducible fixture ([`fixtures/edge_cases.html`](file:///C:/testing/research_execution_20261018/fixtures/edge_cases.html)), we verified three architectural boundary conditions:

### Edge Case 1: Non-Interactive Container Sections

- **Result:** Neither `aria-label` nor `data-action` appeared in the serialized output.
- **Implication:** The serializer enforces strict non-empty content checks, preventing token inflation from empty markup.

## 5. Methodological & Systems Implications

1. **The Fallacy of Metadata Augmentation for AI:**  
   Proposals at standards bodies (W3C/TPAC) recommending that developers embed specialized Schema.org JSON-LD or custom data attributes specifically for AI agents are currently ineffective for agents running standard `browser-use`. The client-side observation serializer discards these tags before the model receives the prompt.
2. **The "ARIA Stuffing" Confound:**  
   When accessibility attributes do survive (on `<button>` elements), they change the reasoning task from relational hierarchy resolution (finding the product card and locating its child button) to direct string matching (reading the product name directly off the button). Any observed performance improvement on such tasks measures target-name co-location, not semantic comprehension.
3. **The Necessity of Dedicated Machine Endpoints:**  
   Rather than attempting to encode machine data inside HTML DOM channels that are vulnerable to serialization pruning, autonomous agent architectures require dedicated out-of-band endpoints (e.g., `llms.txt`, Model Context Protocol APIs) that bypass DOM serialization entirely.

## Abstract

Autonomous web agents powered by Large Language Models (LLMs) are increasingly evaluated on multi-step digital navigation tasks. Existing agent benchmarks (e.g., WebArena, Mind2Web, WorkArena) evaluate models holistically at the whole-task level, treating web pages as monolithic HTML documents, accessibility trees, or screenshot streams. Consequently, they leave unexamined the client-side Document Object Model (DOM) observation pipelines that filter and transform web markup before it enters the LLM prompt. In modern web engineering, data is distributed across multiple technical layers: visible typography, semantic accessibility attributes (WAI-ARIA), developer custom attributes (`data-*`), and structured metadata (Schema.org JSON-LD).

In this paper, we present an empirical systems audit of the **DOM serialization gap**â€”the discrepancy between what exists in the client-side DOM and what actually reaches the LLM context prompt. Through source-code analysis and dynamic observation tracing of modern browser-agent infrastructure (`browser-use 0.13.10`), we prove three critical architectural bottlenecks:
1. Default DOM serializers unconditionally prune `<script>` and `<meta>` elements via `DISABLED_ELEMENTS`, preventing Schema.org JSON-LD structured data from reaching the LLM prompt buffer (0.0% token reachability).
2. The serializer constructs HTML element tags and attributes **only for interactive (clickable/scrollable) elements or frames** (`serializer.py:L1046â€“L1058`). Non-interactive elements (`<span>`, `<div>`, `<section>`) have their tags stripped entirely; parent `aria-label` and `data-*` attributes are discarded, emitting only raw child text strings (0.0% attribute reachability).
3. Custom developer attributes (`data-*`) are stripped by default whitelist filtering unless explicitly overridden by custom runner-level whitelists.

Furthermore, we analyze the methodological implications of these serialization heuristics for behavioral agent benchmarking. When semantic accessibility markup does survive serialization (on `<button>` elements), modifying button labels from generic text (e.g., `"Add to Cart"`) to entity-specific ARIA labels (e.g., `aria-label="Add SoundFlow Air 3 to cart"`) introduces an acute experimental confound: it converts a hierarchical reference resolution problem into direct string matching. We pre-register a 4-arm Randomized Complete Block Design ($N=96$) equipped with hardened ground-truth verifiers and zero-dependency literature-verified statistical estimators (Cochranâ€“Mantelâ€“Haenszel, Newcombe hybrid score CIs). Monte Carlo power simulations (10,000 trials) prove that small-sample agent experiments ($n=20$/arm) possess $<11\%$ power to detect realistic effect sizes ($\Delta \le 0.20$), establishing a strict methodological ban against claiming web markup equivalence from non-significant p-values.

## 1. Introduction & Motivation

Large Language Models (LLMs) paired with browser automation libraries enable autonomous agents to execute complex web workflows [Zhou et al., 2024; Deng et al., 2023; Drouin et al., 2024]. However, raw HTML documents on modern websites frequently exceed 15,000 to 50,000 tokens, far exceeding prompt budget efficiency. To overcome this context-length barrier, modern browser-agent frameworks implement heuristic DOM serialization, pruning non-content elements and stripping non-whitelisted attributes before compiling the observation prompt.

In modern web development, information is represented across distinct technical layers:
- **Visible Typography:** Text rendered inside standard HTML elements (`<p>`, `<span>`, `<h1>`) for human readers.
- **Accessibility Semantics (WAI-ARIA):** Programmatic attributes (`aria-label`, `role`, `aria-describedby`) designed for assistive screen readers [W3C, 2017].
- **Developer Data Attributes:** Custom client-side attributes (`data-action`, `data-product-id`, `data-amount`) utilized by Single Page Applications (SPAs).
- **Structured Data (JSON-LD):** Machine-readable schemas embedded inside `<script type="application/ld+json">` for search engine indexing [Schema.org, 2024].

As standards organizations (W3C/TPAC 2024) debate the emerging "Agentic Web"â€”including proposals to augment web markup specifically to assist AI scrapers or introduce dedicated machine endpoints (`llms.txt`, MCP APIs)â€”a fundamental systems question arises:

> **Do client-side DOM serializers in modern autonomous agent frameworks preserve these metadata channels, or do heuristic pruning algorithms strip them before they can reach the LLM context prompt?**

If an agent framework silently purges structured metadata, web developers' efforts to markup pages for AI agents are completely lost. Furthermore, if academic researchers attempt to benchmark agent performance across markup variants without verifying prompt delivery, they risk testing unaugmented text while attributing performance differences to invisible channels.

### Key Contributions
1. **Architectural Serialization Proofs:** We prove through AST analysis and dynamic observation tracing that standard `browser-use 0.13.10` completely prunes Schema.org JSON-LD scripts (0.0% reachability) and strips attributes on non-interactive containers (`<span>`, `<div>`, `<section>`).
2. **Quantitative Reachability Benchmark:** We deliver an offline, reproducible audit suite ([`audit_metadata_reachability.py`](file:///C:/testing/research_execution_20261018/audit_metadata_reachability.py)) and dataset ([`serialization_audit_metrics.json`](file:///C:/testing/research_execution_20261018/serialization_audit_metrics.json)) quantifying token and attribute reachability across 7 metadata channels and 3 edge cases.
3. **Identification of the Action-Label Confound:** We demonstrate that when ARIA attributes do reach the prompt on interactive buttons, they confound semantic markup comprehension with target-text co-location.
4. **Pre-Registered Methodological Blueprint & Statistical Framework:** We pre-register a 4-arm balanced design ($N=96$) with hardened state-asserted verifiers and zero-dependency statistical implementations (CMH, Newcombe CIs) validated against published literature benchmarks [Agresti, 2002; Newcombe, 1998].
5. **Statistical Power Boundaries:** Through 10,000-trial Monte Carlo simulations, we prove that small-sample agent benchmarks ($n=20$/arm) have $<11\%$ power for realistic effects ($\Delta \le 0.20$), formally cautioning against the Equivalence Fallacy.

## 3. Systems Architecture & Pruning Heuristics (`browser-use 0.13.10`)

We performed a static source-code audit and runtime trace of `browser-use 0.13.10` ([`C:\testing\.venv311\Lib\site-packages\browser_use\`](file:///C:/testing/.venv311/Lib/site-packages/browser_use/)).

### 3.1 Script and Meta Pruning (`DISABLED_ELEMENTS`)
In `browser_use/dom/serializer/serializer.py` (Line 18):
```python
DISABLED_ELEMENTS = {'style', 'script', 'head', 'meta', 'link', 'title'}
```
During tree simplification in `_create_simplified_tree` (Lines 480â€“482):
```python
elif node.node_type == NodeType.ELEMENT_NODE:
    if node.node_name.lower() in DISABLED_ELEMENTS:
        return None
```
Any element matching `DISABLED_ELEMENTS` is immediately pruned. Child nodes are never traversed. Consequently, `<script type="application/ld+json">` structured data and `<meta name="evidence-date">` tags suffer 100% information loss.

### 3.2 Non-Interactive Element Tag Stripping
In `browser_use/dom/serializer/serializer.py` (Lines 1046â€“1058):
```python
is_any_scrollable = node.original_node.is_actually_scrollable or node.original_node.is_scrollable
should_show_scroll = node.original_node.should_show_scroll_info
if (
    node.is_interactive
    or is_any_scrollable
    or node.original_node.tag_name.upper() == 'IFRAME'
    or node.original_node.tag_name.upper() == 'FRAME'
):
    next_depth += 1
    attributes_html_str = DOMTreeSerializer._build_attributes_string(
        node.original_node, include_attributes, text_content
    )
```
If an element is **not interactive** (not clickable, not scrollable, and not an iframe):
- `_build_attributes_string` is **never invoked**.
- No opening or closing tag is output for that element.
- The serializer processes child text nodes, emitting raw strings, but all element attributes (`aria-label`, `data-*`, `role`) are discarded.

### 3.3 Attribute Whitelist Filtering
In `browser_use/dom/views.py` (Line 18), `DEFAULT_INCLUDE_ATTRIBUTES` specifies retained attributes. While standard accessibility attributes (`aria-label`, `role`) are included, developer custom attributes (`data-action`, `data-product-id`) are omitted. In `serializer.py` (Lines 1211â€“1215), attributes are discarded if `key not in include_attributes`.

## 5. Methodological Analysis: Experimental Design & Confounding

### 5.1 The Action-Label Co-Location Confound
When ARIA markup does reach the prompt (on `<button>` elements), it alters the task construct:
- In `v0-baseline`: The agent observes:
  ```
  SoundFlow Air 3
  $49.99
  [12] <button>Add to Cart</button>
  ```
  The agent must perform **hierarchical reference resolution**: locate the heading, verify the price, establish the card boundary, and infer that button `[12]` belongs to SoundFlow Air 3.
- In `v2-aria`: The agent observes:
  ```
  [12] <button aria-label="Add SoundFlow Air 3 to cart">Add to Cart</button>
  ```
  The agent performs **direct string matching**: finding `"SoundFlow Air 3"` directly within the button tag. Any observed accuracy improvement measures label disambiguation, not semantic markup comprehension.

### 5.2 Pre-Registered 4-Arm Protocol v3
To provide a rigorous baseline for future empirical trials, we pre-registered a 4-arm Randomized Complete Block Design (RCBD) across six tasks and four temporal blocks ($N=96$ trials):
- `BASELINE` (ABS, $N=24$): Unaugmented HTML text.
- `BASELINE_REP` (VIS, $N=24$): Baseline replication arm to test within-condition stability.
- `ARIA` ($N=24$): Interactive elements augmented with `aria-label`.
- `DATA-CFG` ($N=24$): Interactive elements augmented with custom developer attributes via extended whitelisting.

### 5.3 Hardened Two-Tier Verifiers
Protocol v3 resolves four scoring flaws identified in earlier benchmarks ([`verifier_specification.md`](file:///C:/testing/research_execution_20261018/verifier_specification.md)):
- **T1â€“T2:** Programmatic assertion of exact SKU matches in `window.__cart__`.
- **T3 (2nd-Highest Audio):** Strictly enforces `len(cart) == 1 and cart[0] == "wh-002"`, rejecting the 6-SKU pass vulnerability of earlier verifiers.
- **T4 (Checkout):** Enforces `order_confirmed == True`, eliminating partial credit on incomplete checkouts.
- **T5 (Cart Removal):** Asserts precondition `pre_cart_count == 1` before checking empty final cart (`len(cart) == 0`).
- **T6 (Absent Fact Probe):** Evaluates grounded refusal vs. hallucinated warranty duration in strict isolation from primary task accuracy.

## 6. Statistical Methodology & Power Boundaries

### 6.1 Task-Stratified Cochranâ€“Mantelâ€“Haenszel (CMH) & Newcombe CIs
To account for task heterogeneity across the $K=5$ primary strata, post-experiment inference utilizes the continuity-corrected CMH test statistic [Agresti, 2002]:
$$\chi^2_{\text{CMH}} = \frac{\left( \left| \sum_{k=1}^K n_{11k} - \sum_{k=1}^K \mu_k \right| - 0.5 \right)^2}{\sum_{k=1}^K \text{Var}(n_{11k})}$$
Risk differences are reported alongside 95% Newcombe hybrid score confidence intervals [Newcombe, 1998] utilizing independent Wilson score limits. In [`test_analyze_v3_results.py`](file:///C:/testing/research_execution_20261018/test_analyze_v3_results.py), our zero-dependency Python implementation matches published clinical trial benchmarks to four decimal places (Agresti 2002: $\chi^2 = 6.3841, p = 0.0115$; Newcombe 1998: $\hat{\theta} = 0.3250$, 95% CI: $[+0.1764, +0.4578]$).

### 6.2 Statistical Power Analysis & The Equivalence Fallacy
Primary contrasts across tasks T1â€“T5 utilize $n=20$ trials per arm. 10,000-trial Monte Carlo simulations ([`power_analysis.json`](file:///C:/testing/research_execution_20261018/power_analysis.json)) establish:
- **$\Delta = 0.70$:** $100.0\%$ power (robustly detectable).
- **$\Delta = 0.35$:** $49.7\% \pm 1.1\%$ power.
- **$\Delta = 0.20$:** **$10.8\% \pm 0.6\%$ power** (Bonferroni $\alpha = 0.0167$).

> [!WARNING]
> **METHODOLOGICAL PROHIBITION OF EQUIVALENCE CLAIMS:**  
> Because the power to detect small performance differences ($\Delta \le 0.20$) is under $11\%$, obtaining $p > 0.05$ cannot be interpreted as evidence that plain HTML and semantic markup perform equivalently. A null result indicates only that the sample size was insufficient to detect subtle effects.

## 8. Discussion & Implications for Web Standards ("The Agentic Web")

1. **The Fallacy of Metadata Augmentation for AI:** Web authors cannot assume that adding Schema.org JSON-LD or custom data attributes will assist AI agents. Under standard `browser-use`, client-side DOM serializers discard these elements before the LLM receives the observation.
2. **The "ARIA Stuffing" Hazard:** In accessibility research, standards bodies (W3C/TPAC) have warned against developers overloading ARIA attributes specifically to optimize for AI agents. If ARIA attributes provide no generalized accuracy advantage over clear typographyâ€”and merely duplicate entity text onto buttonsâ€”stuffing ARIA tags risks polluting accessibility trees for human screen-reader users without aiding AI agents.
3. **The Necessity of Out-of-Band Machine Endpoints:** Rather than attempting to embed machine data in HTML DOM channels that are vulnerable to serialization pruning, standards organizations should prioritize dedicated machine endpoints (e.g., `llms.txt`, Model Context Protocol APIs) that bypass DOM serialization entirely.
